# 킴시디언(Kimsidian) — 기획 · 설계서

> Obsidian + 아메바(Amoeba) 시스템. 영어 1:1 강사를 위한 **진화형 학생 지식 시스템**.
> 본 문서는 기획(Why/What)과 설계(How)를 디테일하게 기술한다.
> 구현 근거: 플러그인 `obsidian-ameba-plugin/`(TypeScript, 약 1,420줄) + 웹앱 `obsidian-ameba/`(약 1,901줄) + 예시 볼트 28개 노트. 헤드리스 엔진 테스트(휴리스틱·의미 경로) 통과.

---

# 1. 기획 (Planning)

## 1.1 한 줄 정의
**킴시디언** = 기존 Obsidian 노트 위에, 학생 데이터가 세대를 거쳐 **스스로 수렴(융합)·발산(분기)하며 진화**하는 "살아있는 학생 프로파일" 레이어(아메바 시스템)를 얹은 도구.

## 1.2 타깃 사용자 & 문제 정의
- **사용자**: 영어 1:1 강사(튜터).
- **문제**:
  1. 학생마다 세션이 누적되면 관찰(발음·문법·어휘·자신감 등)이 **수십 개 노트로 흩어진다.**
  2. "이 학생의 진짜 약점이 뭔가"를 파악하려면 강사가 **수작업으로 패턴을 머릿속에서 통합**해야 한다.
  3. 비슷해 보이는 실수가 사실은 다른 원인(예: 막연한 "발음 문제" → `th` 발음 vs `r/l` 구분)일 때 **세분화가 안 된다.**
  4. 다음 수업 계획을 **데이터 기반으로** 세우기 어렵다.

## 1.3 핵심 가치 제안 (아메바 메타포)
학생 한 명 = 살아있는 **아메바**. 관찰 노트 = **세포**. 시간이 지나며 세포가:
| 현상 | 교육적 의미 |
|---|---|
| **수렴(융합)** | 흩어진 비슷한 관찰들이 하나의 **특질(trait)**로 통합 → "이 학생의 핵심 약점/강점" 가시화 |
| **발산(분기)** | 뭉뚱그린 특질이 **전문화된 하위 특질**로 분화 → 진단 정밀화 |
| **도태** | 일시적·약한 신호는 **자연 소멸** → 노이즈 제거, 본질만 생존 |
| **고도화 지수** | 구조가 정제될수록 오르는 **"천재 지수"** → 학생 이해도의 정량 지표 |

→ 결과물: 강사가 보는 **자동 진단 맵 + 다음 수업 추천**.

## 1.4 산출물 (3종)
- **(A) 실제 Obsidian 플러그인** `obsidian-ameba-plugin/` — *주 산출물*. 기존 Obsidian 위에서 동작.
- **(B) 독립 웹앱** `obsidian-ameba/` — 설치 없이 브라우저에서 도는 데모/공개용.
- **(C) 예시 볼트** `obsidian-ameba/vault/` — 학생 3명 × 세션 6 + 개념 노트 9 = 28개. 데모/테스트용.

## 1.5 유통 · 수익 방향 (확정)
- **1순위: 로컬 GPU AI 우선** — 사용자(강사) PC의 **RTX 6000 Ada**에서 Ollama로 의미 분석 → "의미 기반" 진화 고도화. (프라이버시: 외부 전송 0)
- **2순위: 무료 웹 공개** — GitHub Pages로 휴리스틱 웹앱 공개 → 사용자/평판 확보.
- **추후**: 구독형 클라우드(동기화·AI 백엔드) 또는 옵시디언 커뮤니티 플러그인 등록.

## 1.6 비기능 요구사항
- **프라이버시**: 학생 데이터는 로컬 처리(localStorage / 사용자 볼트 / 사용자 GPU).
- **무빌드 설치**: 플러그인은 빌드 산출물(`main.js`) 포함 → 3개 파일 복사로 설치.
- **테마 호환**: Obsidian CSS 변수(`--background-primary`, `--interactive-accent` 등) 사용 → 어떤 테마에도 자연 융화.
- **그레이스풀 폴백**: AI(Ollama) 없으면 검증된 휴리스틱으로 자동 동작.

# 2. 설계 (Design)

## 2.1 시스템 아키텍처
플러그인은 **관심사 분리된 4개 모듈**:

```
src/
  engine.ts  (381줄)  ── 순수 로직: 벡터화·유사도·융합·분기·도태·점수·추천 (의존성 0, 테스트 대상)
  view.ts    (562줄)  ── 살아있는 포스 그래프: 물리 시뮬레이션 + 캔버스 렌더 + 사이드 패널 + 상호작용
  ai.ts      (131줄)  ── 로컬 LLM(Ollama) 클라이언트: 임베딩 + 채팅 추천 (requestUrl로 CORS 우회)
  main.ts    (264줄)  ── 통합: 볼트 스캔, 임베딩 캐시, 뷰/리본/커맨드/설정 등록
```

**데이터 흐름**
```
노트(frontmatter+본문)
   └─ main.ts: metadataCache + cachedRead → SourceNote[]  (학생별 그룹)
        └─ engine.cellsFromNotes() → Cell[]  (관찰 1개 = 세포 1개)
             └─ view.ts: 물리 루프에서 자발적 융합/분기 → 진화하는 특질
                  ├─ 캔버스: 옵시디언 그래프 비주얼
                  └─ 사이드: 고도화 지수 · 수업 추천 · 진화 로그 · 특질 목록
```

## 2.2 데이터 모델
```ts
SourceNote { path, title, student, category, tags[], strength, session, body }
Cell {                       // 진화의 단위(세포/특질)
  id, members[],             // 이 세포에 기여한 원본 노트 경로들
  subCells[],                // 분기 분석용 잎(leaf) 관찰들
  vec,                       // 키워드 가중 벡터 (태그 4.0 / 본문 상위6단어 0.5)
  emb?,                      // 의미 임베딩(단위 정규화) — AI on일 때
  strength, category, session, label, text, age
}
```
허용 `category`: grammar · vocabulary · pronunciation · fluency · listening · writing · confidence · interests · goals · errors

## 2.3 아메바 알고리즘 (핵심 — 디테일)

### (a) 벡터화 `keywordsOf()`
- **태그**: 가중치 **4.0** (강사가 직접 붙인 라벨 = 최강 신호)
- **본문**: 불용어 제거 후 빈도 상위 **6단어**만 **0.5** (희석 방지)
- 위키링크 `[[...]]`는 텍스트로 펼쳐 키워드에 포함

### (b) 유사도 `similarity(a,b)`
- 휴리스틱: `tagCosine + (같은 카테고리면 +0.22)`
- **AI on**: `semWeight·(의미 임베딩 코사인) + (1−semWeight)·tagCosine + (같은 카테고리 +0.11)`
  - `semWeight` 기본 0.6 (슬라이더 0~1). → **태그가 달라도 뜻이 가까우면 융합**

### (c) 수렴(융합) — *emergent, 충돌 기반* `tryConverge()`
1. 모든 쌍에 유사도 링크 생성(임계 ≥ 0.30). **유사할수록 스프링 rest 길이 짧음** → 끌려감.
2. 물리적으로 **충돌**(거리 < 두 반지름 합의 0.9배) **그리고** `유사도 ≥ mergeThreshold(0.46)` 이면 **융합**.
3. 융합 세포: 멤버·벡터·임베딩(가중평균)·강도(시너지 +0.1) 합성, 라벨 = 상위 키워드.
→ 버튼이 아니라 **시뮬레이션에서 자발적으로** 일어남.

### (d) 발산(분기) — *내부 긴장 기반* `tryDiverge()`
1. `tension(cell)` = **공통(일반) 태그를 제거**한 뒤 하위 관찰들의 평균 비유사도(이질성).
2. `subCells ≥ 3` **그리고** `tension ≥ tensionThreshold(0.52)` 이면 **분기**.
3. **2-means**로 두 모드 분리 → 각 자식은 공통 태그가 제거되어 **서로 유사도 낮음 → 재융합 안 됨** → 두 전문 특질로 갈라져 밀어냄.
   - 예: A~B~C 사슬(A와 C는 안 닮음)이 한 덩이로 뭉치면 긴장↑ → `th-sound` ⟂ `r-l-distinction` 로 분기.

### (e) 도태 `decay()` / `isDead()`
- 매 프레임 `strength −= 0.0006`, 단 멤버 많을수록 `+보강`.
- `strength < 0.08` & 단일 멤버 & `age > 1500` → 소멸(노이즈 제거).

### (f) 고도화 지수 `score()`
```
min(100,  통합특질수×8  +  카테고리커버리지×6  +  평균강도×30  +  수렴률×40)
```

### (g) 수업 추천 `recommendations()`
- 우선순위 = `(1−강도)·0.5 + min(1,멤버/5)·0.3 + (세션/12)·0.2` (약점·빈발·최근 가중)
- 상위 3개 → 카테고리별 한국어 활동 템플릿. **AI on이면** 로컬 LLM이 자연어 추천으로 대체.

## 2.4 물리 시뮬레이션 (옵시디언 그래프 비주얼)
- **반발** `(2600+(rA+rB)·26)/d²`, **중력** `(중심−위치)·0.0022`, **유사도 스프링** `rest=(rA+rB)+70−sim·90, k=0.012+sim·0.03`
- 적분 `x += v·0.5`, 댐핑 `v·0.85` → 안정적·유기적 움직임
- 노드 반경 = `10 + 강도·26 + min(20,(멤버−1)·2.6)`, 카테고리색·글로우·멤버수 링·라벨
- 드래그/줌/팬, 노드 클릭 → 원본 노트 열기, ⏯ 재생/속도(0.5~4×)/재배양
- 색·배경·선 모두 **Obsidian 테마 변수**에서 읽어 렌더 → 네이티브 그래프 미감

## 2.5 AI / 임베딩 설계 (로컬 GPU)
- **Ollama** HTTP API(`localhost:11434`)를 Obsidian `requestUrl`로 호출 → **CORS 무관**.
- 임베딩 모델(기본 `nomic-embed-text`)로 노트 의미 벡터화 → **캐시(본문 해시 키)**, 변경분만 재계산.
- 채팅 모델(기본 `qwen2.5:7b`)로 추천 JSON 생성 → 견고한 파싱 + 실패 시 휴리스틱 폴백.
- 설정: 토글 · 주소 · 임베딩/채팅 모델 · 의미 가중치 · 연결 테스트 · 재계산.
- **RTX 6000 Ada(48GB)** → `qwen2.5:14b/32b` 등 대형 모델도 로컬 구동 가능.

## 2.6 빌드 · 배포 · 테스트
- **빌드**: esbuild(`main.js` 번들) + `tsc -noEmit` 타입체크. `npm run build`.
- **무빌드 설치**: `manifest.json + main.js + styles.css` 를 `<볼트>/.obsidian/plugins/amoeba-system/` 에 복사.
- **웹 배포**: `.github/workflows/deploy-pages.yml` → GitHub Pages.
- **테스트**: `tools/test-engine.mjs` — 시드 볼트로 융합/분기/점수 검증(휴리스틱 + 합성 임베딩 의미 경로). 둘 다 PASS.
